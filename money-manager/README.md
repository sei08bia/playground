# お金の見える化

カード・口座・サブスク・インフラ（光熱費・通信）・ほしいもの・NISA・iDeCo/企業型DC をひとつの画面で管理して、
「今月あといくら使えるか」「今日あといくら使えるか」「使いすぎていないか」を出し、AI（Claude）から家計のアドバイスをもらうためのローカル Web アプリです。

データは手元の SQLite（`data/money.db`）にだけ保存されます。

## できること

| 画面 | 内容 |
|---|---|
| ダッシュボード | 今月あと使えるお金・今日あと使えるお金・純資産／今期の支出ペース（月末の見込み）／カテゴリ別予算／カードごとの次回引き落とし額と利用枠／資産の内訳（預金・投資・年金）と運用成績／1か月以内の引き落とし予定／純資産の推移／生活防衛資金が何か月分あるか |
| 明細 | 手入力と CSV 取り込み（カード会社・銀行の明細、マネーフォワード ME のエクスポート。Shift_JIS/UTF-8 に対応し、同じ明細は二重に取り込まない）。内容から自動でカテゴリ分け。**Gmail からの自動取り込み**（下記） |
| 口座・資産 | 銀行・現金・電子マネー・クレジットカード（締め日・引き落とし日・引き落とし口座・利用枠）・証券口座・NISA・iDeCo・企業型DC・ローン。残高を更新するたびに履歴が残る |
| 固定費・サブスク | サブスク／インフラ／家賃・保険などの固定費／積立投資（NISA積立・iDeCo掛金）。毎月・毎年・毎週に対応し、月額に換算して集計 |
| ほしいもの | 価格・優先度・取り分けている額から「今月の予算で買える／貯金から出せる／待つ」を判定し、何か月で貯まるかを表示 |
| AIアドバイス | 家計の集計値を Claude に渡して診断・質問への回答（例:「4万円のイヤホン買っていい？」「見直すべきサブスクは？」） |

### 「あといくら使えるか」の計算

```
変動費の予算 = 手取り月収 − 固定費・サブスク・インフラ（月換算） − 積立投資 − 先取り貯金
今月あと     = 変動費の予算 − 今期の変動費
今日あと     = (今月あと + 今日使った分) ÷ 残り日数（今日を含む） − 今日使った分
```

- 「家計の始まりの日」を給料日（例: 25）にすると、25日〜翌24日を1期間として計算します。
- 固定費に「照合キーワード」（例: `NETFLIX`）を設定しておくと、カード明細の該当行を固定費の支払いとして扱い、変動費から二重に引きません。
- 今日時点の予定額より使っていて、このままだと月末に予算を超える見込みなら「ペース早め」、超えたら「予算オーバー」と表示します。
- NISA・特定口座は「投資」、iDeCo・企業型DC は「年金（原則60歳まで引き出し不可）」として、すぐ使えるお金（預金 − カード未払い）とは分けて表示します。

## 使い方

```bash
cd money-manager
pip install -r requirements.txt

# （任意）AI アドバイスを有効にする
export ANTHROPIC_API_KEY=sk-ant-...

uvicorn app.main:app --reload
# → http://localhost:8000
```

最初に **設定** で手取り月収を入れ、**口座・資産** と **固定費・サブスク** を登録してから、カード明細の CSV を取り込むのがおすすめです。
NISA・iDeCo の評価額は証券会社のサイトを見て月1回くらい更新すると、純資産の推移がグラフになります。

### デモデータで試す

```bash
MONEY_DB=data/demo.db python -m scripts.seed_demo --reset
MONEY_DB=data/demo.db uvicorn app.main:app --reload
```

### テスト

```bash
python -m pytest
```

## Gmail から自動取り込み

カード会社から届くメールを定期的に読んで反映します（既定 30 分ごと）。

| メール | 反映先 |
|---|---|
| **ご請求金額のご案内**（楽天カードなど毎月の請求額） | カードの次回引き落とし額を、明細からの推定ではなく確定額で表示。取り込んだ明細の合計との差も表示 |
| **ご利用のお知らせ**（三井住友・JCB・エポス・PayPayカード・イオンなど、1 回ごとの利用通知） | 明細として追加。取消・返品の通知は返金として記録 |

- 取り込むのはカード会社のドメインから届いたメールだけです（お店の決済完了メールはカード明細と二重になるので対象外）。キャンペーンやポイントのお知らせは無視します。
- 利用通知で取り込んだ明細と、あとで取り込んだカード CSV の同じ利用（同じカード・同じ金額・日付 ±3 日）は 1 件にまとめます（CSV の内容で上書き）。
- メールのカードは、口座の「金融機関」にカード会社名（例: 楽天カード）を入れておけば自動で紐づきます。同じ会社のカードが複数あるときは「メール照合キーワード」（例: `Mastercard`）で区別します。カード未登録のまま届いた請求額は、カードを登録した後の取り込みで反映されます。
- 楽天カードは 1 回ごとの利用通知をアプリでのみ送るため、メールで取れるのは請求額です。明細は CSV で取り込んでください。
- 解析は各社の典型的な書式（「利用日」「利用先」「利用金額」などのラベル行）に合わせています。読めないメールは「明細」画面の「メール本文で解析テスト」で確認できます。

### 設定

1. Google アカウントで 2 段階認証をオンにして [アプリ パスワード](https://myaccount.google.com/apppasswords) を作る
2. 環境変数を設定して起動する

```bash
export GMAIL_ADDRESS=you@gmail.com
export GMAIL_APP_PASSWORD="xxxx xxxx xxxx xxxx"
uvicorn app.main:app
```

IMAP で読み取り専用に接続し、メールを既読にもしません。アプリ パスワードは環境変数からだけ読み、DB には保存しません。
（Gmail API の OAuth は、個人用の「テスト中」アプリだと更新トークンが 7 日で切れて自動取り込みが止まるため、IMAP にしています。）
IMAP を使わない場合は、Gmail から保存した `.eml` ファイルを「明細」画面から取り込むこともできます。

## AI アドバイスについて

- `ANTHROPIC_API_KEY` があると Claude（既定 `claude-opus-5-5`、`MONEY_ADVISOR_MODEL` で変更可）が回答します。無い場合や API エラー時はルールベースの簡易診断を返します。
- Claude に送るのは **集計値**（予算・残高・カテゴリ別合計・固定費の一覧・ほしいものリストなど）だけで、個々の明細の店名などは送りません（`app/advisor.py` の `build_context`）。
- 安全分類器で回答が断られた場合は、サーバー側フォールバック（`fallbacks: "default"`）で別モデルが自動で回答します。
- 一般的な家計のアドバイスであり、個別の金融商品の売買を勧めるものではありません。

## 構成

```
app/
  main.py        FastAPI のルーティング（REST API + 画面の配信）
  finance.py     集計ロジック（期間・予算・ペース・カードの締め/支払い・純資産・ほしいもの判定）
  service.py     DB から読んで finance に渡す層、純資産の推移
  csv_import.py  明細 CSV の解析とカテゴリ自動判定
  advisor.py     Claude によるアドバイスとルールベースの簡易診断
  mail_parser.py カード会社のメール（利用通知・請求額）の解析
  gmail_sync.py  Gmail（IMAP）からの取得、明細・請求額への反映、定期取り込み
  db.py          SQLite スキーマと設定
static/          画面（素の HTML/CSS/JS、外部ライブラリなし）
scripts/seed_demo.py  デモデータ
tests/
```
